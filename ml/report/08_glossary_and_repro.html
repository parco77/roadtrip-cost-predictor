Part 15Glossary — every technical term used in this project

Alphabetical. If an examiner uses one of these words, this is the definition to give, with the project's own example attached where there is one.

TermDefinition, and where it appears here
AdaBoostAdaptive Boosting. Trains weak learners (usually shallow stumps) sequentially, re-weighting the rows the previous learner got wrong. Consistently the weakest ensemble in this project, because chasing the noisiest rows is the wrong instinct on a smooth additive target.
BaggingBootstrap Aggregating. Trains many models in parallel on bootstrap samples of the rows and averages them, reducing variance. RandomForest is bagging plus random feature subsets per split.
BaselineThe score to beat before a model means anything. For classification, the majority-class rate; for a replaced constant, the constant's own error. Every table in this project carries one.
Bias (statistical)Systematic error — being wrong in the same direction on average. The winding-factor constant is nearly unbiased (−0.4%) yet wrong by 6.3% per route, which is the distinction Part 10 turns on.
Bias–variance tradeoffError decomposes into bias² (model too simple) + variance (model fits noise) + irreducible noise. Capping the traffic classifier's max_depth at 4 added bias, cut variance, and improved the test score.
BootstrapResampling the data with replacement to estimate the variability of a statistic. Used here as the alternative to k-fold: 200 resamples gave a 95% interval of width 3e−6.
BoostingTraining models sequentially, each correcting its predecessors' errors. Attacks bias, unlike bagging which attacks variance.
Chained model / pipelineFeeding one model's output into another's input. This project chains six sub-models into a cost regressor. See also stacking.
Coefficient / weightThe number a linear model multiplies a feature by. Because features here are scaled to 0–1, each weight reads as “rupees of change as this feature goes from its minimum to its maximum”.
Condition number κRatio of largest to smallest eigenvalue of the Hessian; how “stretched” the loss surface is. At κ ≈ 16,000 the surface is a long narrow valley, which is why gradient descent stopped converging on weights in Part 9.
Confusion matrixA table of actual class against predicted class. Shows how a classifier fails, not just how often — this project's traffic errors concentrate between adjacent levels, which is the right failure mode for an ordered target.
Convex functionA function with a single minimum and no local minima. MSE for linear regression is convex, which is why gradient descent and the normal equations must reach the same answer.
Correlation (Pearson r)Strength and direction of a linear relationship, from −1 to +1. fuel_consumption_litres correlates +0.9606 with the target; passengers −0.0468.
Cross-validation (k-fold)Split the training data into k parts, train on k−1 and validate on the rest, k times. Gives a mean and, more usefully, a standard deviation that reveals instability.
cross_val_predictProduces out-of-fold predictions: each row's prediction comes from a model that did not see that row. Essential for building stacking features without optimism.
Data leakageInformation from outside the training data influencing the model, making evaluation optimistic. This project had it — a scaler fitted before the split — and fixed it with Pipelines.
DecisionTreeRecursively splits the feature space on thresholds. Grown to purity it memorises the training set (train R² = 1.0000), which is why it is the project's clearest overfitting example.
Design matrixThe X matrix of features, rows = samples, columns = features.
Dummy variable trapKeeping all one-hot columns of a group makes them sum to 1 in every row, which is collinear with the intercept and makes the matrix singular. Avoided with drop_first=True.
EpochOne full pass of gradient descent over the training data. This project's six-feature fit converged at epoch 14,317 of a 50,000 budget.
F1 scoreHarmonic mean of precision and recall, 2PR/(P+R). Penalises a model that is good at one and bad at the other.
Feature engineeringConstructing new input columns from existing ones. The project's largest single accuracy gain: adding litres × price cut MAE from ₹143.85 to ₹42.60.
Feature importanceHow much each feature contributed. For trees, impurity reduction; for a scaled linear model, |coefficient|. It reports what the model used, not what is true — see the vehicle one-hot trap in Part 9.7.
GradientBoostingBoosting where each new tree is fitted to the residuals of the ensemble so far. Won the traffic classification here.
Gradient descentIterative optimisation: compute the loss, compute its gradient, step in the opposite direction. Implemented from scratch in NumPy in Part 7.
GridSearchCVExhaustive search over every combination in a parameter grid, scored by cross-validation. Used for Ridge α and the traffic classifier.
HaversineGreat-circle (straight-line) distance between two points on a sphere. The starting point for road distance, which is always longer.
HessianMatrix of second derivatives of the loss; describes the curvature of the loss surface. Its condition number is what diagnosed the Part 9 problem.
HyperparameterA setting chosen before training, not learned from data — learning rate, number of trees, max_depth, Ridge α. Contrast with parameters (weights), which are learned.
Interaction termA feature formed by multiplying two others, letting an additive model express a product. This project's central technique — used for the fuel bill, for the litres model's traffic multipliers, and for the mileage model's nine cells.
IQR methodOutlier rule: drop points outside [Q1 − 1.5×IQR, Q3 + 1.5×IQR]. Removed 11 of 1,140 rows in Part 4.
Irreducible errorError no model can remove because the data itself is random. Here: toll noise (±₹219) and parking noise (±₹50), which together with the fuel-bill term account for ₹529 of the ₹596 RMSE.
L1 / L2 regularisationL1 (Lasso) penalises ∑|w| and can force weights to exactly zero, so it selects features. L2 (Ridge) penalises ∑w² and shrinks weights smoothly without zeroing them.
Learning rateStep size in gradient descent. Too small and it never arrives (lr = 0.001 left weights 2,025 away); too large and it diverges (above lr ≈ 0.44 here). This project uses 0.2.
LinearRegressionFits ŷ = Xw + b by minimising squared error. sklearn solves it in closed form via the normal equations. The model this project ships.
LogisticRegressionLinear model for classification — fits a linear function then squashes it through a sigmoid/softmax into class probabilities. Best model on cost_band.
Loss functionThe quantity being minimised. Here MSE, (1/n)∑(ŷ − y)².
Macro vs weighted averagingMacro weights every class equally; weighted weights by class frequency. Macro is reported here because weighted averaging can hide a class the model never predicts — demonstrated by macro F1 0.2248 at 50.88% accuracy on the original data.
MAEMean absolute error, (1/n)∑|y − ŷ|. The number to tell a user. Served value here: ₹391.16.
MinMaxScalerRescales each feature to 0–1 via (x − min)/(max − min).
MSE / RMSEMean squared error and its square root. RMSE reads in the target's units and penalises large errors more heavily than MAE.
MulticollinearityFeatures strongly linearly related to each other. The fit stays valid but individual coefficients become unstable. Here: corr(litres, fuel_bill) = 0.989.
Multiple linear regressionLinear regression with more than one feature: ŷ = w₁X₁ + … + wₖXₖ + c.
Normal equationsThe closed-form solution w = (XᵀX)⁻&sup9;Xᵀy. Exact, one step, and indifferent to the condition number — which is why this project ships it instead of gradient descent.
One-hot encodingTurning a categorical column into one binary column per category, asserting no ordering between them.
One-standard-error ruleModel-selection rule from Hastie, Tibshirani & Friedman §7.10: among models within one standard error of the best CV score, choose the simplest, because smaller differences are not real.
Out-of-fold predictionA prediction for a row made by a model trained without that row. The correct way to build stacking features.
OverfittingLearning the training data's noise; good train score, poor test score. Seen here on cost_band (gap 0.21) and the toll sub-model (gap 0.37).
Pipeline (sklearn)Chains transformers and a final estimator into one object, so cross-validation re-fits the transformers per fold. The fix for this project's scaler leak.
PrecisionTP/(TP+FP) — of the items predicted positive, how many were. “When it says High traffic, how often is it right?”
R²Coefficient of determination, 1 − RSS/TSS. Fraction of variance explained. Compresses meaningful differences when the target is nearly deterministic.
RandomForestBagged decision trees with random feature subsets per split. Strongest ensemble here; wins where the relationship is genuinely non-linear.
RandomizedSearchCVSamples a fixed number of random hyperparameter combinations instead of trying all. Covers a bigger space for a fixed budget.
Rank deficiencyWhen columns of the design matrix are linearly dependent, so infinitely many weight vectors give identical predictions. Why the fixed-pair city one-hots were dropped in Part 7.
RecallTP/(TP+FN) — of the items that are positive, how many were found.
RegularisationPenalising weight size to reduce variance. Rejected here after measuring that it cost six times the error.
Residualy − ŷ. Studying residuals is how Part 5 recovered the generating formula.
Ridge regressionLinear regression with an L2 penalty: w = (XᵀX + αI)⁻&sup9;Xᵀy.
RSSResidual sum of squares, ∑(y − ŷ)². A sum, so comparable only within one split.
StackingUsing base models' outputs as a meta-model's inputs. This project's chained pipeline, built with out-of-fold predictions.
Stratified splitA split preserving each class's proportion in both halves. Used for all classification splits here.
Target / labelThe column being predicted. Here total_trip_cost.
Train/serve mismatchTraining a model on inputs of a different quality from what it receives in production. Measured explicitly here — and it cost essentially nothing, because the sub-model errors are zero-mean.
UnderfittingModel too simple, or features too weak, to capture the relationship; poor on both splits. All five classifiers on the original dataset's traffic target.
Variance (of a model)Sensitivity to which particular training rows were seen. High-variance models score well on train, poorly on test.
Winding factorThis project's term for road distance ÷ straight-line distance. Observed mean 1.2520, range 1.0437 to 3.6015 across 840 real routes — the variation a single constant cannot express.

Part 16How to reproduce every number in this report

16.1 Just run it

cd backend
pip install -r requirements.txt
uvicorn app:app                  # -> http://127.0.0.1:8000   the API

cd ../frontend
npm ci
npm run dev                      # -> http://127.0.0.1:5173   the UI

Two processes locally, because there are two in production. Vite proxies /api to port 8000, so no backend URL is configured for local work and development exercises the same relative paths the deployed build does.

No training step is needed to serve a prediction: both model bundles and the two data files the API reads at import are committed beside it in backend/.

16.2 Rebuild everything from scratch, in order

Run from ml/. Note where the outputs land: a script that produces something the server loads writes it into backend/, and the distance table is written into frontend/. There is no copy step to forget, because there is no copy.

python scripts/build_cities.py           # 3,739 cities, real lat/lon  -> backend/data/
python scripts/build_fuel_prices.py      # per-state fuel prices       -> backend/data/
python scripts/build_wide_dataset.py     # 25,000 trips over real geography
python scripts/fetch_real_distances.py   # 840 REAL road distances from OSRM   (~6 min)
python scripts/build_distance_matrix.py  # -> frontend/public/city_distances.json

python scripts/train_pipeline.py         # -> backend/models/pipeline.joblib  (the sub-models)
python scripts/train_models.py           # -> backend/models/model.joblib     (band + curve)

python scripts/evaluate_models.py        # -> ml/data/task5_evaluation.json   (~5 min)
python scripts/build_report_pdf.py       # -> ml/Project_Report.pdf  (this document)

cd ../backend && pytest -q              # 70 tests

Where the order is load-bearing, and where it is not. The data builders run first because everything downstream reads their output. train_pipeline.py and train_models.py are independent of each other — both fit from the CSV, neither loads the other's bundle — but evaluate_models.py reads pipeline_report.json, so it must follow the first of them, and build_report_pdf.py reads all three JSON reports, so it must be last. It re-runs its own two generated chapters on every build, so this document cannot quote a number older than the run that produced it.

16.4 Reproducibility guarantees

  • Every random operation is seeded. random_state=42 for all splits and models; a fixed seed for route sampling and for the bootstrap.
  • Verified in practice. After re-running the whole pipeline to fix the model file sizes, every metric returned bit-identical — R² 0.981574, MAE ₹291.69, distance MAE 30.67 km.
  • One scoring module. Every metric in this report comes from scripts/evaluation.py, and the two generated chapters read the JSON it writes, so this document and the API cannot quote different numbers for the same model.
  • One feature contract. backend/roadtrip_features.py names each model's columns and their order once. The training scripts import that file out of backend/ rather than keeping a copy, so a feature added for training cannot go missing at serve time — which is the failure the arrangement exists to prevent.
  • 70 tests pin the behaviour, including the error budget and the honest reporting.

Closing note

If only one thing from this report is remembered, make it this: the project reports R² 0.9816 and MAE ₹292 as its accuracy, not the R² 0.9998 that appears in Parts 8 and 9. The larger number is real but was measured with the model holding the two terms that carry its own uncertainty. Knowing the difference — and being able to explain why the difference exists — is what the ten weeks were actually for.
